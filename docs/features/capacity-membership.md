# 容量限制与会员接入

实现分支：`codex/do-less-capacity`，基于 `v1.1.9`。

## 本地行为

每个工作空间：10 张贴图、4 个自建快捷动作标签、每个分类 12 个可见动作（系统“其他”也单独限 12 个）、3 个提醒列表、每列表 7 条未完成提醒。隐藏动作不计数，重新显示需要检查。旧数据不截断，编辑、完成、删除与撤销不因超额被拦截。

- 超额文字批次先预览，自主选取可容纳的内容。余项以一份当前草稿保存在本机，支持复制和下载。
- 手动新增满额时提供独立输入草稿，输入不中断；多行提交再走批量选择。
- 待添加图片只在当前页面会话保留，离开页面有提示；图片原文仍使用 IndexedDB，不写入 localStorage。
- 同步超额提醒作为 `pendingInbox` 随工作空间持久化，与水位线在同一次保存中提交。原消息身份用路由哈希和消息 ID 组合，不包含配对码。部分接纳后只移除已接纳项；放弃需要确认，也不会清除另一份输入草稿。
- 中继现有代码的保留期是 30 天（`server/app.py` 的 `RETENTION_MS`）。电脑长期未接收的消息不等于已备份。本机保存失败不推进本地水位线；本地存储不是无限空间。
- 当前导入入口是完整的单空间文件恢复/新增空间，没有普通逐条合并导入入口；该恢复流程保留超额存量。以后如增加逐条合并，必须使用同一套增长判定。
- 专注任务内的参考图片继续沿用原模型，本次贴图配额作用于原密度阈值对应的工作空间贴图区。

配额与净增长判定位于 `src/state/capacity.ts`；交互文案位于 `src/state/capacityText.ts`；草稿位于 `mini-desk-capacity-drafts-v1`。草稿与权益独立于工作空间导出：导出空间数据不会包含授权或购买恢复码。

## 真实收款的前置配置

前端已实现报价、订单二维码、核对支付结果和恢复购买的适配层。用户已确定一次性 **19.9 元、支付宝收款码**，二维码稍后提供。弹窗显示金额、支付渠道与“收款码待提供”；订单/授权服务尚未配置，默认仍显示“容量解锁暂未开放购买”，不会生成示例收款码。静态收款码不能证明订单成功，提供图片后仍须确定可兑现的授权发放流程。

Vite 构建变量：

```text
VITE_MEMBERSHIP_API=https://your-membership-service.example
VITE_MEMBERSHIP_PUBLIC_KEY={"kty":"EC","crv":"P-256","x":"...","y":"..."}
```

第二项必须是公开 JWK，不包含私钥 `d`。商户支付密钥、签名私钥和支付回调密钥只留在服务端。接口跨域时服务端配置实际站点的 CORS；不发送桌面内容。

### 服务端接口契约

所有金额均为人民币分，最终价格以服务端商品配置为准。前端不提交自定义金额。

`GET /offer`：

```json
{
  "id": "capacity-once",
  "amount": 1990,
  "currency": "CNY",
  "channel": "alipay",
  "description": "一次性解除五项数量限制；实际售后说明由商户提供",
  "supportUrl": "https://your-service.example/support"
}
```

金额 1990 分对应用户确定的 19.9 元；支付渠道为支付宝。适配层保留微信能力，但本次不启用。

`POST /orders`，请求：

```json
{"offerId":"capacity-once","idempotencyKey":"client-generated-stable-key"}
```

返回：

```json
{
  "id": "opaque-order-id",
  "qrUrl": "https://real-provider-issued-alipay-payment-url",
  "expiresAt": 1800000000000,
  "recoveryCode": "unguessable-purchase-recovery-code"
}
```

只有用户看过最终报价并点击购买后才请求订单。网络响应不确定时重试使用相同幂等键；服务端必须按该键返回同一个订单，不重复创建收款意图。二维码到期后用户可以主动创建新订单，旧订单仍可核对。

`POST /orders/{id}`，请求：

```json
{"recoveryCode":"unguessable-purchase-recovery-code"}
```

未付款或处理中返回 `{ "license": null }`，真实付款核实后返回 `{ "license": { "payload": "...", "signature": "..." } }`。服务端必须核对商户、订单、商品、金额、支付状态和恢复码归属，并幂等发放授权；前端“已付款”动作或任意布尔值都不能作为证明。

`POST /restore`，请求 `{ "recoveryCode": "..." }`，返回同结构的已确认授权。恢复码是购买凭证，接口应有访问保护、速率限制和实际售后恢复方式。恢复授权不会导入或覆盖桌面内容。

### 授权格式

- `payload` 是以下 JSON 的 UTF-8 字节经 base64url 编码得到的字符串。
- `signature` 是对 **payload 字符串本身的 UTF-8 字节**做 ECDSA P-256 / SHA-256 签名后的 base64url 编码。
- 签名使用 WebCrypto 的 IEEE P1363 格式（64 字节 `r || s`），不是 ASN.1 DER。

```json
{
  "id": "opaque-license-id",
  "product": "mini-desk-capacity",
  "issuedAt": 1790000000000
}
```

可选 `expiresAt` 为毫秒时间戳。前端检查产品、签发时间、到期时间及签名，验证后才保存权益；刷新和窗口重新获得焦点时读取、验证本地授权，离线有效授权可继续使用。付款成功仅解锁容量，不自动填充内容。

这是本地优先前端的权益适配，不提供不可绕过的 DRM。无到期时间的离线授权无法在完全离线时即时撤销；若需要退款后撤销，必须在服务端另定授权期限、在线刷新及离线宽限策略，不能把“浏览器本地签名验证”宣传成即时退款撤权。
