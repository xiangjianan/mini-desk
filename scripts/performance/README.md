# 大数据交互性能测试

使用独立端口，避免污染日常数据：

```sh
npm run dev -- --port 5187 --strictPort
```

打开 `http://127.0.0.1:5187/scripts/performance/index.html`。
首次打开仅在该源没有保存状态时生成 600 条提醒（6 × 100）、600 个快捷动作（6 × 100）和 60 张 1200 × 800 JPEG 测试图片。数据按应用本身的迁移/持久化流程处理。不要将测试页部署到生产站点，也不要在日常使用的端口运行。

依次操作：提醒列表收起/展开、快捷组收起/展开、提醒条目拖动、快捷动作拖动、整组拖动、图片拖动，以及拖动中滚动与 Escape 取消。

每次 pointerdown 开始 1800ms 采样，右下角输出帧间隔最大值、P95、超过 34ms 的帧数、几何测量次数、DOM 节点数，以及浏览器支持时的 Long Tasks 和 Long Animation Frames。超过 5ms 的几何测量附带调用栈。

一次操作后等待采样完成再操作。自动化测试期间不要截图或读取大规模可访问性树，以免观察动作本身扰动测量；避免同时运行测试、构建等高负载任务。对比必须保持同一浏览器、窗口尺寸、数据规模与操作路径。

这些是开发环境的交互样本，不是跨设备性能保证。P95 的窗口包含动画结束后的空闲帧，不能当成持续拖动 FPS。内置图片颜色简单、压缩率高，不能代表几十张高像素照片或动图的解码和内存压力。页面的几何计数包装器本身也有少量开销。
